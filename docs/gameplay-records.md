# Gameplay records and template-based editing
FNV record projects now cover 24 types. Direct constructors: GMST, GLOB, CLAS, FACT, SPEL, CONT, MISC, STAT, AMMO, LVLN, KEYM, ALCH, LVLI, FLST, PERK, VTYP, ECZN and REPU. Template-based: NPC_, RACE, WEAP, ARMO, PACK and MGEF. Source files must be explicitly supplied locally. No retail assets or templates bundled. The examples are original fixture designs, not complete game-ready assets.
- Factions: ranks, directed relations, flags, linked reputation. Fame/infamy percentages in quest dialogue conditions via GetReputationPct, with explicit axis and comparison operator.
- Characters: template clone with exact master-prefix preservation; NPC health, SPECIAL, level, barter gold, AI aggression/confidence/mood/energy/responsibility, service flags, inventory, faction ranks, class/voice/race and AI package links. Voice type and class records can be authored from scratch. Faces and inherited native data retain the source template; new FaceGen, template flattening and complete NPC generation are not implemented. Source self-references continue pointing to the original. Auto-calc fields can supersede explicit stats in game.
- Equipment: clone source WEAP/ARMO, edit title, value, condition/health, weight, damage/clip or damage threshold. Existing animation, effects, models, slots and sound data are preserved. New weapons/armor entirely from scratch not implemented. Ammunition uses an explicit projectile binding.
- Inventory: container, item/key, leveled item and NPC lists, cycle checks for local leveled lists, typed dependencies, draft deletion guards. Merchant service and stock data are separate authoring capabilities, not complete vendor chest wiring. External list cycles are not proven absent.
- Actor effects, food/medicine, perk abilities/quest-stage effects, encounter zones. No arbitrary effect scripts, perk entry points or complete recipe system. Magic effects and AI packages use a local native template; schedules and services flags are editable.
- Compressed staged edits now decode bounded zlib streams and preserve compression flag, all other records and exact untouched subrecords within the decoded payload.
- Master permutation expanded to exact generated non-template gameplay layouts. Unknown tags, arbitrary nested groups and opaque templates are refused. Master addition/removal and unrestricted FormID remapping remain pending.

Template example: {"id":"NewTrader","type":"NPC_","fields":{"template":{"plugin":"Source.esm","id":2048},"title":"New Trader","level":3,"barter_gold":200,"services":["food","repair"]}}. Supply --master Source.esm and all its masters in the original order. The user must own/have rights to source data. Exact prefix constraint ensures retained FormIDs retain meaning; it does not validate every opaque embedded field. No source file is modified.
The official Mutagen 0.54.4 package has a Fallout3 assembly and a broad record definition model, including Reputation, NPC, Armor, Weapon, etc. This is not evidence every FNV format is independently supported. Direct bridge still pending, with GPL dependency kept separate from MIT core.
