# Historical identity policy

Independent implementation using public format documentation. No proprietary SDK used.

Ownership order is a proposed deterministic breadth-first allocation strategy, not proven Creation Kit behavior. Existing identities take precedence. Runtime slot encoding is separate from file master indexing. The new reservation API is opt-in; existing exporters and legacy ledger defaults are unchanged. Extended light ranges require explicit caller selection; zero is conservatively excluded. The legacy ledger still starts at 0x800.

References: https://dyndolod.info/Messages/Invalid-Object-ID and https://en.uesp.net/wiki/Tes5Mod:Mod_File_Format/TES4 . Next steps: native cursor ingestion, editor integration, and independent retail fixture verification.
