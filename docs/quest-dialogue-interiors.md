# Quest and dialogue development; interior layout
Portable quest graph: visual selection, creation, text editing and choice connections; JSON remains available for complete flag conditions. Bounded state exploration models all-false initial Boolean flags, reports reachable deadlocks, states without any route to terminal and unreachable stages. An exceeded state budget reports incomplete, never successful. No engine-specific scripting semantics.
Native New Vegas fixture authoring: explicit separate JSON format for QUST stages, completion/failure flags, objectives, DIAL topics, INFO responses, emotion, choices, previous-response ordering, and GetStageDone conditions. Generated scripts are empty placeholders, quest is not start-game enabled, no NPC assignment, objective targets, automatic stage advancement, external faction/reputation dependencies or compiled script bytecode. Do not silently convert portable flag semantics into native records. Need GECK/xEdit validation and real game tests. Skyrim aliases and SCEN records require separate adapters; New Vegas has a different conversation system.
    python -m chimster quest-states portable.json
    python -m chimster quest-native native.json Quest.esp

## Interior layout
Portable axis-aligned room bounds, rectangular portal corners on shared faces, trigger boxes with event IDs, and linked nodes with room ownership. Conservative visibility candidates traverse open portals; closed portals can eliminate disconnected rooms, not a full portal frustum/culling renderer.
    python -m chimster interior-check rooms.json --room A --closed Door
Next: visual placement and visualization; portal frustum clipping; native REFR XPRM/XTRI/XRMR/XLRM/XPOD/XPTL, occlusion planes, multibounds, collision/trigger scripts, lighting and acoustic spaces, pathgrid/navmesh and linked-reference support. Need per-game base forms and exact flags; do not invent or bundle retail records. Oblivion, FO3/FNV, Skyrim and FO4 need separate schema verification.
References: https://tes5edit.github.io/fopdoc/FalloutNV/Records/QUST.html ; DIAL.html, INFO.html, REFR.html, Subrecords/CTDA.html in same documentation.

## Dependency-aware follow-up
Supply every dependency in load order with repeatable --master PATH. Bind references by {"plugin":"Origin.esm","id":2048}, not global load-order FormIDs. Verify type, deletion state, dependency order and source fingerprints, write the MAST table, and relocate the new quest and dialogue records to their own file slot. Objective targets (QSTA) resolve placed reference types; optional speaker (ANAM) resolves NPC_/CREA; response conditions may use {"actor":{"plugin":"Origin.esm","id":2048},"is":true} or {"faction":{"plugin":"Origin.esm","id":2049},"member":true}. These use native GetIsID/GetInFaction conditions. No automatic actor creation or runtime validation.
    python -m chimster quest-native native.json Quest.esp --master Origin.esm
    python -m chimster quest-scripts actions.json script-source
The separate action specification includes quest id, stages (index, optional actions), objectives (index), and topics (id, responses with optional begin/end actions). Actions: {"op":"stage","index":10}, {"op":"display","index":10,"value":true}, {"op":"complete","index":10,"value":true}, {"op":"start"}, {"op":"stop"}. Exports GECK result script text and slot manifest; compile in GECK against the actual plugin. No fabricated SCDA, automatic attachment or native execution. Direct recursive stage actions are rejected; indirect loops still require review.
Portable trigger session detects enter/exit by successive positions, not swept volumes. Portal visibility adds rejection for rectangles wholly outside a supplied camera frustum plane, followed by conservative connectivity. No recursive aperture clipping, occlusion planes or renderer integration.
