# Starfield rendering preview (experimental)
The desktop viewport's Starfield cell preview reads full ESM/ESP masters in explicit load order using bounded streaming scans rather than loading an entire large plugin into RAM. It previews selected-cell placed reference markers, DAT2 point/spot lights (including shadow spotlights), XRDS radius overrides, XCLL cell ambient/directional/fog settings, supported WATR visual fields and explicit cell water height. The existing Panda and ModernGL effects path consumes the report. Light intensity is a bounded lumens approximation, not exact Starfield PBR exposure. Game unit scale is explicit. No native record changes, no small/medium/overlay master support, no runtime ID translation, no planet terrain, no native NIF/external .mesh geometry or material decoding; model paths are collected as a future adapter boundary. No unverified old Fallout record offsets. No third-party source or assets vendored; no paid dependencies.

Format references: Mutagen Starfield Light.xml, Light.cs, Cell.xml, PlacedObject.xml and GameConstants.cs at https://github.com/Mutagen-Modding/Mutagen ; xEdit SF1 record definitions https://github.com/TES5Edit/TES5Edit/blob/dev-4.1.5/Core/wbDefinitionsSF1.pas . Synthetic fixtures are not retail-file certification.

Static external .mesh version 0–2 geometry is now importable directly, including positions, primary UVs and up to three supplied index LODs. Skinning is explicitly rejected; v2 trailing meshlet data is not interpreted. A bounded optional JSON sidecar maps a relative NIF path to an already extracted .mesh path, e.g. {"version":1,"models":{"meshes/example.nif":"geometries/example.mesh"}}. This supports actual mapped geometry in cell previews without claiming BSGeometry NIF reference resolution. Layout reference: https://github.com/fo76utils/nifskope/blob/develop/src/io/MeshFile.cpp ; independent Python reader, no upstream code or assets copied. Normals are recomputed by the portable renderer. No paid libraries.

BA2 v2/v3 GNRL and DX10 header variants, bounded raw LZ4 texture chunks, ordered archive/loose assets and DDS reconstruction now feed the existing mesh manifest route. Source: https://github.com/fo76utils/fo76utils/blob/main/libfo76utils/src/ba2file.cpp (MIT); independent Python implementation. Unknown variants still fail closed.

Automatic native NIF resolution supports sized little-endian Starfield NIF blocks (BS versions 170/172/173/175), NiNode/BSFadeNode hierarchies, external BSGeometry slots, composed local transforms and up to three external LODs. Unsupported scene graph types, controllers, skinning, embedded geometry and count mismatches fail closed to the existing proxy. Source layout: https://github.com/fo76utils/nifskope/blob/develop/build/nif.xml . No external executable or copied implementation required.

Native BSLightingShaderProperty name indices identify .mat paths per BSGeometry. An optional preview map connects these IDs to archive or loose DDS textures and scalar metallic/roughness, normal, tint and cutout settings; Panda PBR applies the scalar metallic/roughness values. ModernGL uses the derived legacy gloss. This is deliberately not a native layered .mat or materials.cdb decoder; unmapped materials use the existing fallback.

Additional static scene nodes (ordered, multibound, switch/LOD active child, range, fade and leaf nodes) and embedded BSGeometry streams are recognized. Meshlet/cull footers are checked for bounds rather than left opaque. Optional bind-pose decoding validates and skips skin weights; it is not skeletal deformation, and remains opt-in in the Python API. Native animation is still excluded.
