# Record editing development
Section 3, initially New Vegas. Typed inspector and staged same-name editing for selected existing fields (text, model paths, global values, GMST values, item/book value and weight, bounds, reference transforms and scale, static passthrough sound). Unknown fields remain raw/read-only; compressed and deleted records cannot be edited. All other record payloads are checked. Reference transforms must be independently checked against world ownership after an edit.
Persistent FormID ledger is opt-in for world, quest and record-project generation. Keys include signature and stable ID; world cells/LAND use world ID and absolute cell coordinates. Placement and INFO identities require explicit IDs. Retired identities are reserved; restoring the same key restores the same ID. Keep the ledger with the exact same named plugin. Renaming a key creates a different identity. Ledger is not inferred from existing saves or retail plugins. New plugin and new ledger are staged, never overwrite existing output. This is not a crash-atomic two-file commit; keep old revisions. Sequential mode remains for legacy tests.
Record project: create GMST/GLOB/FACT/MISC/STAT/FLST records, local symbolic references and explicit external origin/local-ID references. Removing a draft record is blocked when known local FLST entries refer to it. No deletion of arbitrary existing plugin records, no claim of save-safe removal. Desktop project editor uses JSON and masterless exports; dependency binding via CLI. Side-by-side record comparison shows typed field values and raw previews. Master permutation supports the exact flat schemas generated by the record builder and remaps LNAM and record header IDs. Refuses unknown fields, compressed records, nested groups, master addition/removal, arbitrary local renumbering. No general remap yet.
Commands:

    python -m chimster fnv-world heights.json World.esp --spacing-m 4 --content content.json --ledger-out world-ids.json
    python -m chimster quest-native native.json Quest.esp --ledger-out quest-ids.json

## Bounded master set changes
The same-name staged New Vegas writer now accepts explicit master additions and removal of unused masters for the existing exact generated top-level schemas. The default remains permutation-only. Example:
    python -m chimster master-reorder Source.esp stage/Source.esp A.esm B.esm --allow-master-set-change
To remove every unused master, omit the master paths and retain the opt-in flag. The operation checks dependency order, source record identity uniqueness, surviving override origins, known target types, and reference resolution; unknown schemas, nested groups, compressed/flagged records and referenced removed masters are refused. Output is independently reopened using Chimster's scanner, not an external engine. Changing the master set or order may change winning overrides or runtime behavior even if origin/local identities are preserved; review with an independent editor before deployment. New synthetic fixtures await execution.

## Generated exterior hierarchy and compressed records
The staged writer now supports the exact generated exterior WRLD/CELL/LAND/REFR hierarchy, typed LTEX/TXST links and generated BOOK/NOTE layouts. Group owner identities and grid labels are checked on reopen. Known-schema compressed payloads use bounded decoding and recompression. Other nested groups (including arbitrary interiors/dialogue), opaque fields and unsupported flags still fail closed. Source inspection only; new synthetic regression fixtures await execution.

## Script-free generated quests
Master-table staging supports exact generated New Vegas QUST/DIAL/INFO layouts and type-7 topic-owned groups; known CTDA parameters and quest/dialogue links are remapped by origin. Nonempty result scripts and unknown conditions are refused. Graph inspection shares the generated quest and world offsets. No blanket quest/script compatibility or runtime certification. Regression execution deferred.


## Shared native typed workbench
The native workbench now discovers and edits a conservative subset of existing inline display names, typed GMST values, and GLOB values for Morrowind, Oblivion, Fallout 3, New Vegas, Skyrim, Skyrim SE, and Fallout 4. TES3 uses FNAM for display names and NAME for persistent named settings/globals; TES4-family formats use FULL and EDID respectively. Localized string fields, duplicate scalar fields, deleted records, unknown layouts and profiles outside this explicit allowlist remain unavailable for this adapter. This does not enable Starfield or Remastered writes or certify VR formats. Existing specialized typed adapters remain available through the transaction API.
The NativeSession apply_typed method uses revision-checked atomic batches; identity and record type changes are refused. The desktop workbench exposes common typed fields, eight-step undo/redo, and validated create-only staged export through native_save. Unknown subrecord bytes remain intact. Source plugin files are not edited. Synthetic fixtures cover seven profile layouts, compressed global records, failed batch rollback and stale revisions. Independent editor and game verification remains required.


### Gameplay property inspector expansion
The desktop inspector now displays individual typed properties, field signatures and repeated-entry occurrences in a selectable grid. It uses revision-checked edits, undo/redo and staged export. It exposes existing Morrowind item, spell, NPC/creature, AI/service, inventory and leveled adapters, classic Oblivion fixed-layout item and actor properties, FO3/FNV weapon and armor DATA candidates, Skyrim LE/SE weapon and item DATA candidates, and FO4 miscellaneous item DATA. Existing FO3/FNV book data and supported classic leveled entries are included. Selected full-slot CNTO counts are editable without changing the referenced FormID; unsupported layouts, duplicate fixed fields and deleted records are excluded from discovery. This is a bounded candidate schema, not unrestricted game-format editing. VR, Remastered and Starfield remain separate schema verification tasks.
Synthetic fixtures exercise per-game property mutations, occurrence-specific inventory edits and rejection of unknown properties. The GUI still needs actual desktop verification and independent engine checks.
