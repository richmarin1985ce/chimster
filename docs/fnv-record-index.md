# FNV record index and first native AutoPatch writer
Independent MIT implementation. The incremental SQLite record index is specific to FNV-style 24-byte headers and full master slots, not a generic TES4 parser. It records provider, origin/master identity, local ID, record type, flags, offset, EditorID where uncompressed and raw payload SHA-256. Compressed payloads are hashed as stored; raw byte digests are not semantic equality. No reference traversal, light plugins or field merging. Refresh a dedicated per-profile cache, then query a chain in the supplied active order. All input files are hashed on refresh; only changed files are parsed. No game runtime validation or performance claims yet.

The experimental GMST writer creates an ESP for explicitly selected existing numeric/string setting overrides (IDs >= 0x800) belonging to one self-contained ESM. It copies only plain EDID/DATA winning records; disallows unsupported flags/layouts, unknown types, missing masters, reserved IDs and source-name collisions. It does not deactivate source plugins, write to game directories, merge arbitrary records, or prove save compatibility. Validates its own round-trip only; xEdit and engine tests are required before use. Use disposable fixtures.

Reference: https://tes5edit.github.io/fopdoc/FalloutNV/Records/TES4.html and https://tes5edit.github.io/fopdoc/FalloutNV/Records.html
