# Expansion-scale native authoring testbeds

Section 3 remains the overriding engineering priority. These original fan expansion projects are downstream integration targets, not claims of playable releases. No retail assets are redistributed.

| Target | Project | Setting |
|---|---|---|
| Fallout New Vegas | Fallout: Route 66 | Existing Flagstaff campaign and surrounding highway region |
| Skyrim | Provisional: Realm of Order | Jyggalag, original realm interpretation; no major Skyrim questline; lore review required |
| Fallout 3 | Fallout: Baltimore (working title) | Baltimore harbor, industrial districts and surrounding neighborhoods |
| Fallout 4 | Fallout Nautica | Nantucket and maritime locations |
| Morrowind | Coldharbour (working title) | Ruined, distorted reflections of selected Vvardenfell locations; distinct from Project Tamriel |

Target per expansion: approximately 10–15 hours main story and 20–30 hours including optional content, 25–40 authored locations, multiple settlements or hubs, original factions and quests. These are planning targets, not verified equivalence to Dragonborn. Prioritize a small playable vertical slice before expanding content. Each project should exercise native record identity, reference traversal, world/cell hierarchy, dialogue, quests, scripting, NPCs, inventory, localization, assets, conflict handling and save/load validation where supported. TES3 uses its own record identity semantics rather than TES4 FormIDs. Skyrim and FO4 require separate versioned schemas. Retail tests require locally owned game installations; no certification without execution. Separate Skyrim original/SE and FO4 version targets as needed. Additional game families remain outside these five testbeds.
